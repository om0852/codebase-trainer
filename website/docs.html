Codebase Trainer docs

Set it up, learn the eight tools, configure it for your team, and see exactly how it was measured.

Quick start

Run one command in the root of your repository, restart your editor, and ask your agent a question.

STEP 1

Register the server and build the index

TERMINAL · REPO ROOT
npx codebase-trainer setup

It finds the editors you use and adds codebase-trainer to their project config (.mcp.json for Claude Code, .cursor/mcp.json, .vscode/mcp.json), keeping any other servers in those files. Then it indexes the repo. Add --dry-run to see what it would write, or --client claude cursor to choose.

STEP 2

Restart your editor

The editor starts the server itself (npx -y codebase-trainer mcp) from the repository folder. Commit the config files so your team gets the same setup.

STEP 3

Ask

PROMPT
Use codebase-trainer feature_slice to show me everything involved in password reset,
then tell me which files I need to change to add rate limiting.

Requirements

Node.js

22 or later (22.13+ recommended)

The index uses Node's built-in node:sqlite. On Node versions without it, the index falls back to a JSON file automatically. Tested on Node 22 and 24.

Operating system

Windows, macOS, Linux

CI runs the full test suite on all three. Paths are reported with forward slashes on every platform.

Git

Any recent version

Needed for diff review, test selection for your working-tree changes, and learning commit conventions. Everything else works without it.

Disk and memory

About 2.4 KB of index per file

A 10,000-file repo needs about 24 MB in .codebase/. The server keeps the index and parsed files in memory while it runs.

Connect your editor

npx codebase-trainer setup does this for you. To do it by hand, add the server to your client's config. The server indexes the folder it is started in, so use project-level configs where your client supports them.

Claude Code

Project config, committed with the repo: .mcp.json at the repo root.

.mcp.json
{
  "mcpServers": {
    "codebase-trainer": { "command": "npx", "args": ["-y", "codebase-trainer", "mcp"] }
  }
}

TERMINAL
claude mcp add --scope project codebase-trainer -- npx -y codebase-trainer mcp

.cursor/mcp.json in the repo (or Settings → MCP → Add new server with the same command).

.cursor/mcp.json
{

    "codebase-trainer": { "command": "npx", "args": ["-y", "codebase-trainer", "mcp"] }
  }

VS Code (Copilot agent mode)

.vscode/mcp.json in the repo. Note the servers key and type.

.vscode/mcp.json
{
  "servers": {
    "codebase-trainer": { "type": "stdio", "command": "npx", "args": ["-y", "codebase-trainer", "mcp"] }
  }
}

Windsurf and other clients

Windsurf keeps a per-user file, ~/.codeium/windsurf/mcp_config.json, with the same mcpServers entry; npx codebase-trainer setup --client windsurf writes it. Any MCP client that can start a stdio server works: the command is npx -y codebase-trainer mcp, started in the repository folder.

Faster start with a global install

npm install -g codebase-trainer, then use cb-trainer with args ["mcp"] instead of npx. Upgrade with npm install -g codebase-trainer@latest.

Using it with an agent

Agents pick tools from their descriptions, so naming the tool helps the first few times. These are the moments it pays off most.

Before changing a feature
"Use codebase-trainer feature_slice for 'article comments' and list what I'd need to touch to add comment editing."

One call instead of a dozen greps and file reads.

Before a refactor
"Run codebase-trainer impact on src/lib/session.ts, then give me the command to run the affected tests."

Dependents, other references, and the tests that reach the file.

Understanding a flow
"Use codebase-trainer trace_flow to show how checkout goes from the page to the database."

Ordered steps with file:line evidence, and a Mermaid diagram.

Before you commit
"Run codebase-trainer review_diff on my changes and fix anything it reports."

Secrets, broken imports, contract drift and permission problems on changed routes.

Auditing access
"Use codebase-trainer api_map with section permissions and explain each finding."

Routes without guards, deletes allowed by edit scopes, read scopes on writes.

Joining a codebase
"Use codebase-trainer codebase_overview and summarise the conventions I should follow here."

Conventions with the evidence behind each, module diagram and hotspots.

How it works

Everything runs inside one local Node.js process. No API keys, no vector database, no language server, no telemetry.

1

Parse

TypeScript, TSX, JavaScript and Python are parsed with tree-sitter (grammars ship in the package). Other languages use pattern-based extractors.

2

Link

Imports (tsconfig paths, workspace packages), call sites, client requests to route handlers, ORM calls to models, dependency injection, tRPC procedures and auth guards become one graph.

3

Index

Syntax-aligned chunks in a SQLite database (.codebase/index.sqlite) with BM25 terms and PageRank scores. Only changed files are re-indexed.

4

Serve

Eight MCP tools over stdio, each with a token budget. While the server runs it watches the repo, so no tool call re-scans it.

Honest limits

  • Static analysis: dynamic dispatch, runtime configuration and guards applied where a router is mounted are not traced.
  • feature_slice favours recall: about a third of the files it returns were labelled as needed, the rest are neighbours a change often touches.
  • The permission map is a heuristic with evidence, not a security audit. It checks for a signed-in user, not whether that user may act on a record.
  • Search is keyword-based unless you opt in to the neural model; it matches word families (resolve / resolver / resolution), not synonyms.
  • Best on JavaScript and TypeScript; Python is partly supported, Go, Java and Rust only lightly.

Configuration

Nothing needs configuring. For team-wide settings, commit a codebase-trainer.yaml at the repo root. Unknown or malformed settings are ignored and reported by codebase_overview.

codebase-trainer.yaml
exclude: ["generated/**", "**/*.snap"]   # on top of .gitignore and .codebaseignore
embeddings: false                         # or { enabled: true, model: Xenova/all-MiniLM-L6-v2 }
auth:
  guards: [ensureTeamMember]              # your own auth middleware, for the permission map
  publicPaths: ["/api/status"]            # routes that are public by design
budgets:
  defaultTokens: 8000                     # per tool call
  featureSliceTokens: 6000

What is indexed

Source, config and docs files up to 500 KB that are not excluded by .gitignore, .git/info/exclude, .codebaseignore or the built-in list (node_modules, dist, build, .next, virtualenvs, caches). Credential files such as .env and *.pem are never indexed, and secrets inside indexed files are redacted.

Environment variables

CODEBASE_TRAINER_AUTO_REFRESH=0Do not re-index changed files before a search; results from changed files are marked stale.
CODEBASE_TRAINER_EMBEDDINGS=0Turn neural search off even if the repo opted in.
CODEBASE_TRAINER_MODEL_CACHEWhere the neural model is stored (default ~/.cache/codebase-trainer/models).
CODEBASE_ENCRYPTION_KEYEncrypt the index at rest (AES-256-GCM); init --encrypt creates a local key instead.
CODEBASE_TRAINER_PARSER=regexUse the pattern-based extractors instead of tree-sitter.

Files it writes

Everything generated lives in .codebase/ (index, conventions, reports); add it to .gitignore. Commit codebase-trainer.yaml and your editor's MCP config instead.

Optional neural search

A small local model whose ranking is fused with keyword search by reciprocal rank fusion. It runs on your CPU; nothing leaves your machine. Without opting in, nothing is downloaded.

Encrypted indexes keep neural search off, because vectors would be stored unencrypted. Teams can switch it on for everyone with embeddings: true in codebase-trainer.yaml.

CI and code scanning

Review every pull request with the same checks and see findings in GitHub's Code Scanning tab.

.github/workflows/review.yml
name: codebase-trainer review
on: pull_request
permissions:
  contents: read
  security-events: write
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - uses: om0852/codebase-trainer@v1
        with: { base: "origin/${{ github.base_ref }}" }
      - uses: github/codeql-action/upload-sarif@v3
        if: always()
        with: { sarif_file: codebase-trainer.sarif }

Without the action: npx codebase-trainer review --base origin/main --format sarif --output review.sarif. The step fails on error-severity findings (such as a committed secret); set fail-on-error: false on the action to only report.

Where it is still weak

  • feature_slice precision is 33% against the labels, below our 60% target, and tRPC monorepos (t3-turbo) score lowest.
  • Neural search doubles search time (90–160 ms on these repos) and the first embedding of a repo takes 20–70 s.
  • A one-shot CLI command that needs call edges on a 10,000-file repo still parses every file the first time (about 13 s); the MCP server does this in the background.
  • The permission rules about scopes are only tested on fixtures: none of the four apps uses scopes.

Reproduce with npm run bench:setup && npm run bench. Results, labels and scripts are in bench/.

Upgrading from 1.x

  • Node 22 or later is required.
  • The index moves from .codebase/embeddings.json to .codebase/index.sqlite and is rebuilt automatically on first use.

Troubleshooting and FAQ

My editor says the MCP server failed to start

Check node --version is 22 or later, and that npx -y codebase-trainer mcp starts in a terminal (it waits silently for input; press Ctrl+C). On Windows, if npx is not found by the editor, install globally and use cb-trainer with args ["mcp"].

It indexed the wrong folder

The server indexes the folder it is started in. Use a project-level config (.mcp.json, .cursor/mcp.json, .vscode/mcp.json) so your editor starts it in the repo, or run setup from the repo root.

The first call is slow on a big repo

The first index and the first call graph parse every file once (seconds on a 10,000-file repo). The server does this in the background right after it starts, and after that only changed files are processed.

Does any code leave my machine?

No. No tool makes network calls, and a test runs all eight with sockets, DNS and fetch disabled. The only download is the optional neural model, after you enable it.

Results look out of date

Changed files are re-indexed before every search, and the server watches the repo. If you set CODEBASE_TRAINER_AUTO_REFRESH=0, results from changed files are marked stale; run cb-trainer update. To start over, delete .codebase/.

A finding is wrong

Findings are static heuristics with evidence; check the evidence lines. For the permission map, add your own guard names under auth.guards and public routes under auth.publicPaths in codebase-trainer.yaml. Please report false positives on GitHub.
